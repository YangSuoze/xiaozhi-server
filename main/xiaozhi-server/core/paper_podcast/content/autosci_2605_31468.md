# 论文信息

- 标题：AutoSci: A Memory-Centric Agentic System for the Full Scientific Research Lifecycle。
- 作者来自北京大学，论文版本日期为 2026 年 5 月 29 日。
- 核心问题：科研智能体不能只完成一次问答或一个实验任务，还要贯穿文献理解、选题、实验、写作和审稿回复，并跨项目保存可复用的知识与经验。
- 作者认为完整系统需要四项能力：完整科研生命周期、受控执行框架、结构化持久记忆、能够修改自身流程的系统演化。

# 核心架构

AutoSci 由四个模块组成：SciMem、SciFlow、SciDAG 和 SciEvolve。论文报告的系统规模包括 30 多个科研技能、9 类可复用多智能体算子、10 种记忆实体和 20 多种实体关系。

## SciMem：结构化持久记忆

SciMem 把记忆分成两个区域：

1. 长期知识记忆保存跨项目复用的知识，包含 Topic、Paper、Foundation、Concept、Method、People 六类实体。实体以 Markdown 页面保存，通过受约束的双向关系形成可遍历知识图谱。
2. 活跃研究记忆保存当前项目快速变化的产物，包含 Idea、Experiment、Manuscript、Review 四类实体。每类实体都有生命周期状态，例如想法可处于 proposed、testing、validated 或 failed，实验可处于 planned、running、completed 或 abandoned。

记忆通过三种方式增长：长期知识内部聚合；长期记忆与活跃项目之间双向流动；跨研究周期积累审稿意见、失败经验和回复结果。所有写入先经过 Trust Guard，分别检查结构是否合法、内容是否有证据支持，并给出 PASS、WARN 或 BLOCK。被阻止的内容先隔离，避免错误污染未来项目。

## SciFlow：受控的科研生命周期

SciFlow 将科研拆成五个阶段：Literature 文献、Ideation 构思、Experiment 实验、Writing 写作、Rebuttal 审稿回复。阶段之间通过 SciMem 的显式读写传递产物，而不是依赖临时聊天记录。

它的执行框架提供五项保证：

- State：在模型上下文之外记录阶段产物和进度，因此任务可以恢复。
- Context：每个技能只获得当前所需的记忆视图，而不是整个知识图谱。
- Verification：重要写入和阶段交接经过结构检查与基于证据的审查。
- Feedback：失败、批评和证据不足被当成流程信号，可以触发修正。
- Orchestration：负责停止点、非阻塞长实验、监控以及阶段调度。

## SciDAG：可选的多智能体增强

SciDAG 不是独立流水线，而是 SciFlow 中困难技能可以调用的工具。它把 generate、variation、debate、ensemble、test、refine、review 等算子组织成有向无环图。节点产生中间结果，边可以根据质量、成本和收敛情况决定继续、重试、分支、剪枝或停止。输出仍遵守 SciFlow 原来的产物契约，因此下游阶段不需要了解内部用了多少智能体。

论文强调按需使用多智能体，而不是所有步骤都堆很多智能体。常用图会保存为按阶段组织的模板，并根据执行轨迹继续调整。

## SciEvolve：可审计的系统演化

SciEvolve 将用户纠正、实验结果、失败原因、新论文、代码库和投稿要求等信号，转成有版本记录的系统更新。整体循环是感知信号、提炼重复模式、修改系统、部署新版本、监控结果。

- `/dream` 维护 SciMem，可降权或归档过时内容、压缩重复信息、合并实体和建立新关系。
- `/forge` 修改 SciFlow 技能。技能被视为包含输入、上下文、步骤、检查、输出和交接规则的版本化协议，而不只是提示词。
- `/morph` 根据多智能体执行轨迹修改 SciDAG，可调整角色和工具、剪掉弱分支、增加验证节点或为特定问题专门化模板。

论文声称的“自我演化”不是模型参数训练，而是修改记忆组织、技能协议、提示词、工具配置和编排模板。

# 案例与实验结果

论文给出两个端到端案例。GPU 内核优化在 4 张 NVIDIA A40 上运行，使用 Triton 3.2.0、PyTorch 2.6.0 和 TritonBench；生物医药案例在单张 RTX 4060 上运行 DeepTernary、PROTAC-STAN，并对部分目标使用 Boltz-2 交叉检查。两个案例都使用由 Opus 4.7 驱动的 Claude Code 智能体。

GPU 案例先提出五条候选路线，再做新颖性和预算筛选，最后选择“性能分析引导的 Claude Code 内核优化”。这里有一个重要限定：论文明确说明图中的第二阶段筛选是根据实际硬件上限做的演示性重建，并非正式的事前筛选。

GPU 实验先从 184 个算子提示中筛出 156 个可行算子。主实验对 157 个算子执行五轮优化；第五轮时 157 个生成内核都可执行且结果正确。相对匹配基线的几何平均加速为 1.52 倍；排除退化基线后为 1.18 倍。消融实验报告性能反馈在高提升空间组带来 1.58 倍收益，在更广泛组带来 1.22 倍收益。系统还分析了 628 次迭代变化，发现结构性修改集中在早期，后期更多是小规模自动调参。

两个案例生成论文级产物分别耗时 27.3 小时和 22.6 小时。作者把生成论文提交给 PaperReview.ai，并以 ICLR 为目标会议，得到 6.3/10 和 5.8/10。作者明确说这些自动评分只是论文级代理指标，不能替代正式同行评审。评审指出外部有效性有限、缺少对照实验、测量噪声和表达不完整等问题。

# 可以讨论的关键判断

1. 论文最有价值的贡献可能是系统工程：把状态、证据、记忆和恢复机制放在模型对话之外，而不一定是提出了新的基础模型能力。
2. 结构化记忆比简单向量检索更容易审计和追踪证据，但人工设计实体类型与关系可能带来维护成本和模式僵化。
3. Trust Guard 能降低错误传播风险，但内容检查仍依赖另一个智能体，不能保证事实正确。
4. SciDAG 的按需多智能体设计比固定多智能体流水线更节省成本，但论文没有充分量化它相对单智能体的独立贡献。
5. SciEvolve 有版本和审计记录，风险小于直接让系统任意改写自己；不过它主要修改非参数组件，和模型真正学习新能力不是同一件事。
6. 两个案例说明系统可以生成完整产物，但不足以证明它能稳定适用于不同科学领域。

# 论文自己承认的局限

- 当前实现仍是建立在通用编码和推理智能体之上的技能包，还不是专门为科研设计的智能体基础设施。
- 完整科研系统缺少成熟的分项评测基准，论文主要依赖两个端到端案例和自动审稿代理分数。
- 生物医药案例得到的是透明但不完整的负结果论文，仍缺少部分比较实验。
- GPU 案例只覆盖一种模型、一个硬件家族和一套基准，外部有效性有限。
